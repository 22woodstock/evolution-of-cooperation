# 협력의 지도 (Map of Cooperation)

반복 사회적 딜레마에서 **어떤 전략이 실제로 유리한가**를 직접 두어 보며 확인하는 웹 게임.

- 매 라운드 **상황이 바뀐다.** 조별 과제, 무인 가게, 구조 보트 — 구조는 같고 문구만 다르다.
- 상대가 어떤 전략인지는 **판이 끝나야 공개된다.**
- 배신이 쌓이면 **제재가 붙어 점수가 음수로 떨어진다.**
- 내가 두는 동안 **컴퓨터 전략들도 자기들끼리 계속 대국한다.**
- 땅은 **누적 총점**으로 나뉜다. 같은 전략을 또 만나면 그 땅이 더 커진다.

## 실행

`index.html`을 브라우저로 열면 끝. 설치할 것도, 서버도 없다.
깃허브에 올린 뒤 Settings → Pages → Branch를 `main`으로 두면 바로 공개된다.

## 기본 점수

| | 상대 협력 | 상대 배신 |
|---|---|---|
| **내가 협력** | 3 / 3 | 0 / 5 |
| **내가 배신** | 5 / 0 | 1 / 1 |

한 판은 20~30라운드이고, **라운드 수는 알려주지 않는다.** 마지막 라운드를 알면
거기서 배신하는 게 항상 이득이라 실험이 망가진다.

## 살아 있는 세계 — 노출 균등 설계

지도가 **실시간으로** 공정하려면, 사후 보정이 아니라 구조로 해결해야 한다.
핵심 원칙은 하나다. **매 순간 모두가 같은 라운드 수를 갖는다.**

- 12전략이 6쌍으로 **동시에** 대국한다. 노는 전략이 없다.
- 나는 그중 한 전략의 **복제본**과 둔다. 원본은 원본대로 리그를 뛴다.
- 내가 한 라운드 두면 6쌍 전부가 한 라운드씩 나아간다.
- 모든 대국이 같은 길이라 한꺼번에 끝나고, 그때 땅이 재분배된다.
- 짝짓기는 원형 방식 라운드로빈이라 11사이클이면 전원이 전원을 한 번씩 만난다.

### 왜 복제본과 두는가

내가 전략 X와 두면 X는 세계에서 1라운드 + 나와 1라운드 = **다른 전략의 2배로 노출**된다.
땅이 누적 총점이므로 X만 2배 속도로 커진다. 실력이 아니라 우연히 나를 만났다는 이유로.

그래서 내 상대는 X의 복제본으로 두고, 그 점수는 지도에 반영하지 않는다.
(분석용으로 `matches` 시트에는 그대로 남는다.) 원본 X는 리그에서 다른 전략과 똑같이
한 라운드씩만 나아간다.

### 검증

600라운드 시뮬레이션 결과다.

```
24사이클 중 노출 불균등:  0회
최종 전원 라운드 수:      585 (편차 0)
땅 비율 vs 평균 비율 괴리: 0.0000%p
```

마지막 줄이 핵심이다. 땅의 비율과 라운드당 평균의 비율이 **완전히 일치**한다.
땅이 실력만 반영하고 노출량은 반영하지 않는다는 뜻이다.

### 클릭 속도

세계는 **시간이 아니라 클릭 수**로 나아간다. 빨리 누르든 20초를 고민하든
한 번 누르면 세계도 한 라운드다. 그래서 참가자의 속도가 땅에 영향을 주지 않는다.

고민 시간은 `rt_ms`에 따로 기록된다. 둘을 섞으면 둘 다 해석할 수 없게 되므로 분리했다.
아무 생각 없이 클릭한 참가자를 걸러내고 싶다면, 게임 규칙을 손대지 말고
분석 단계에서 `rt_ms` 평균이 지나치게 짧은 판을 제외하는 편이 깔끔하다.

### 주의

`표본 늘리기` 버튼은 컴퓨터끼리만 돌리므로 **내 비중이 줄어든다.**
제재 조건을 비교하는 실험용으로만 쓰고, 본 실험 중에는 누르지 않는 것이 좋다.

## 땅을 나누는 기준

```
그 전략의 땅 = max(0, 누적 총점) / 모든 참가자의 누적 총점 합 × 400칸
```

총점을 쓰되 **노출이 구조적으로 균등**하므로, 결과적으로 땅은 실력에 정비례한다.
누적이면서 동시에 공정하다. 누적 총점이 음수면 땅을 한 칸도 갖지 못한다.

순위표에는 `칸 / 총점 / 평균 / 협력률`이 함께 나온다. 둘은 다른 질문에 답한다.

- **총점(=땅)** — 이 세계에서 얼마나 많은 몫을 차지했나
- **평균** — 한 라운드당 얼마나 잘했나

노출 균등 설계를 넣기 전에는 이 둘이 어긋났다. 팃포탯이 땅 1위였지만 평균은 4위였고,
많이 등장해서 땅이 컸을 뿐이었다. 지금은 노출이 같아서 둘의 순위가 항상 일치한다.
**이 변경 전후를 비교하면 그 자체가 좋은 방법론 논의가 된다.**

## 제재 규칙

기본 점수만으로는 "배신을 계속하면 이득"이 학습될 수 있다. 그래서 두 종류의 벌점을 얹었다.

**① 착취 벌점 — 도발자만 깎인다**
상대가 협력하는데 나만 배신한 횟수가 3회를 넘으면, 이후 그런 배신마다 최대 -4점씩 **나만** 깎인다.

**② 갈등 벌점 — 양쪽 다 깎인다**
맞배신이 4회 연속을 넘으면 라운드마다 최대 -3점씩 **양쪽 모두** 깎인다.

**③ 보복자 경감 — 이게 핵심이다**
갈등을 먼저 일으키지 않은 쪽은 ②의 벌점을 25%만 받는다.

③이 없으면 실험이 망가진다. 실제로 시뮬레이션해 보면, 보복까지 똑같이 처벌할 경우
**무조건 협력이 1위**가 되고 팃포탯이 5~6위로 밀린다. 그냥 당하고만 있는 게 최적이 되어
게임이 성립하지 않는다. 도발자와 보복자를 구분해야 균형이 잡힌다.

## 확인된 결과 — 사람이 팃포탯처럼 600라운드를 둔 경우

| 순위 | 전략 | 칸 | 총점 | 평균 | 라운드 |
|---:|---|---:|---:|---:|---:|
| 1 | **나** | 42 | 1,534 | 2.62 | 585 |
| 2 | 너그러운 팃포탯 | 39 | 1,453 | 2.48 | 585 |
| 3 | 파블로프 | 37 | 1,366 | 2.34 | 585 |
| 4 | 팃포탯 | 36 | 1,341 | 2.29 | 585 |
| … | | | | | |
| 13 | **무조건 배신** | **2** | **85** | 0.15 | 585 |

라운드 수 열이 전부 585로 같다는 점을 보라. 이것이 공정성의 증거다.
사람이 팃포탯 전략으로 두면 1위가 되는데, 사람은 상대의 정체를 모르는 상태에서도
그만큼 할 수 있다는 뜻이다.

## 상황 카드 18종

같은 게임을 매 라운드 다른 옷으로 입힌다. 다섯 계열로 나뉜다.

| 계열 | 예시 |
|---|---|
| 학교 | 조별 과제, 족보 공유, 발표 공로, 동료 평가 |
| 공공 | 급식 줄, 무인 가게, 공유 자전거, 지하철 자리 |
| 자원 | 도서관 콘센트, 예산 신청, 우물 배급, 회비 정산 |
| 관계 | 우산 나눠 쓰기, 중고 거래, 소문 |
| 위기 | 구조 순서, 백신 배분, 산불 방화선 |

전략은 이 문구를 **보지 않는다.** 오직 C/D 구조만 본다.
그래서 사람의 선택이 계열마다 달라진다면, 그건 순전히 문구가 만든 차이다.
게임은 계열별 협력률을 자동으로 기록한다. (프레이밍 효과)

## 전략 12종

무조건 협력 · 무조건 배신 · 팃포탯 · 의심 많은 팃포탯 · 두 번 참는 팃포탯 ·
너그러운 팃포탯 · 그림 트리거 · 파블로프 · 탐색꾼 · 다수결 · 번갈이 · 랜덤

## 균형 조정하기

`RULES` 상수 하나만 고치면 전체가 바뀐다.

```js
const RULES = {
  roundsMin: 20, roundsMax: 30,
  eFree: 3, eStep: 1, eCap: 4,   // 착취 벌점
  sFree: 4, sStep: 1, sCap: 3,   // 갈등 벌점
  retal: 0.25,                   // 보복자 경감
};
```

`retal: 1`로 두면 보복자도 똑같이 처벌받는다. 그 상태로 자동 리그를 돌려
순위가 어떻게 뒤집히는지 비교하면, 그 자체가 실험 결과가 된다.

## 새 전략 추가

`STRATEGIES`에 한 항목만 넣으면 지도와 순위표에 자동 반영된다.

```js
HANDSHAKE:{ name:'악수', color:'#8FD3C7',
  desc:'첫 두 수로 암호를 보낸다. 상대도 같은 암호를 냈으면 협력, 아니면 배신.',
  move:(me,opp)=>{ const n=me.length;
    if(n===0) return 'D';  if(n===1) return 'C';
    return (opp[0]==='D' && opp[1]==='C') ? 'C' : 'D'; }},
```

## 조작

`1`은 위 선택지, `2`는 아래 선택지. 20~30라운드를 빠르게 넘길 때 편하다.

## 알아 둘 점

- 순위는 **참가한 전략 구성에 따라 바뀐다.** 7종일 땐 그림 트리거가 1위였지만
  12종으로 늘리자 팃포탯 계열이 올라섰다. 버그가 아니라 이 실험의 핵심 결과다.
- 기록은 브라우저 localStorage에 남는다. 브라우저를 바꾸면 초기화된다.

## 데이터 수집

판이 끝날 때마다 그 판의 전 라운드가 구글 스프레드시트로 전송된다. 시트 네 장에 나뉘어 쌓인다.

| 시트 | 한 행의 단위 | 주요 열 |
|---|---|---|
| `rounds` | 라운드 하나 | 선택, 상황, 기본 점수와 벌점(분리), 누적, 제재 상태, **반응 시간** |
| `matches` | 판 하나 | 상대 전략, 총점, 협력 횟수, 정체 추측과 정답 여부 |
| `world` | 배경 대국 하나 | 두 전략, 라운드 수, 각자 점수 |
| `sessions` | 참가자 하나 | 참가 코드, 동의 시각, 그때의 규칙 설정 |

### 설계 의도

**긴 형식으로 쌓는다.** 한 행에 한 라운드씩, 아래로 길게. 피벗테이블로 언제든 요약할 수 있지만
요약해서 저장하면 되돌릴 수 없다.

**반응 시간(`rt_ms`)을 기록한다.** "위기 상황에서 협력률이 높았다"만으로는 약하지만,
"게다가 결정에 더 오래 걸렸다"가 붙으면 훨씬 강한 주장이 된다.
갈등 끝에 협력한 것과 반사적으로 협력한 것은 다른 현상이다.

**기본 점수와 벌점을 나눠 저장한다**(`my_base` / `my_pen`).
합쳐 두면 "제재가 없었다면 어땠을까"를 사후에 계산할 수 없다. 나눠 두면 데이터만으로 비교가 된다.

**설정값을 같이 저장한다**(`rules_ver`). `retal`을 바꿔 가며 실험할 때
어떤 조건에서 나온 데이터인지 구분할 수 있다.

### 안전장치

- **오프라인 큐** — 전송 실패 시 localStorage에 쌓아 두고 다음 판에 재시도한다.
  화면 하단에 대기 행 수가 항상 보인다.
- **중복 방지** — 각 행에 `참가코드-판번호-라운드번호` 형태의 `uid`가 붙는다.
  재시도로 같은 행이 두 번 들어가도 Apps Script의 `dedupe()`로 정리할 수 있다.
- **익명 코드** — 첫 접속 시 `P-8F3K` 같은 코드를 발급한다. 이름도 이메일도 받지 않는다.
- **동의 화면** — 무엇이 기록되고 무엇이 기록되지 않는지 밝히고, 버튼을 눌러야 게임이 시작된다.
- **읽기 불가** — Apps Script에 `doGet`을 만들지 않았다. 주소를 알아도 쓰기만 되고 읽을 수는 없다.

### 설치

`apps-script.gs` 파일 상단의 주석에 절차가 적혀 있다. 게임 쪽은 `SYNC` 상수만 맞추면 된다.

```js
const SYNC = {
  url:   '…/exec',      // Apps Script 웹 앱 URL (스프레드시트 주소가 아니다)
  token: '…',           // Apps Script의 TOKEN과 반드시 동일하게
  on:    true,          // false로 두면 전송 없이 혼자 테스트할 수 있다
};
```

## 앞으로 할 것

- [ ] 실수 확률 — 의도와 다른 수가 5% 확률로 나가게 하고 뉘우치는 팃포탯 추가
- [ ] 보수 행렬 교체 — 사슴사냥, 치킨게임으로 바꿔 순위 비교
- [ ] 세대 교체 — 점수 높은 전략이 다음 세대에 더 많이 등장하는 진화 모드
- [x] 여러 사람 기록 합산 — 스프레드시트 자동 수집 완료
